# Socialbrewery

Multi-organisation posting app. One Node process serves the UI, the API, and the Grok MCP connector.

- Start with `npm start`, which runs `bin/socialbrewery.js`. That supervisor forks `src/server.js`.
- `.env` holds only server settings (`HOST`, `PORT`, `APP_URL`) and the Clerk keys (`CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`). Changing it needs a restart.
- Everything that posts is per organisation: `src/context.js` runs each request, connector call, and agent run inside `runWithOrg(ctx)`. Read keys with `cfg.X` (never `process.env.X`) and org files through `orgDataDir()`. There is no fallback to `process.env` for organisation keys.
- Organisation settings and network tokens are encrypted (`src/secure.js`, AES-256-GCM, AAD bound to the org). Never send secret values to the browser: `orgSettingsView` returns `set: true` instead, and a blank value means "keep".
- Auth is Clerk. Users, organisations, members, roles, and invites live in Clerk; the dashboard uses `@clerk/react` (sign-in, organisation switcher, `OrganizationProfile`) and sends the Clerk session token as `Authorization: Bearer` (navigations use Clerk's `__session` cookie). `src/clerk.js` verifies that RS256 token with Web Crypto (JWKS from the Backend API, or `CLERK_JWT_KEY`), including issuer, `azp`, and expiry, and never trusts claims it has not verified. `src/accounts.js` keeps one record per organisation keyed by Socialbrewery's own 24-hex id (data paths and encryption AAD are bound to it) with `clerkId`; `orgForClerk` links a Clerk organisation on first use. Network OAuth callbacks can outlive the one-minute Clerk token, so `/api/<network>/connect` sets a signed 20-minute `sb_connect` ticket that only `/api/<network>/callback` accepts. Non-GET `/api` requests must be same-origin. Roles come from the token: Clerk `admin` (or a custom `owner`) > `member`. Settings, connect/disconnect, and connector rotation need admin.
- The Grok connector is `POST /mcp`; its token is looked up by hash and selects the organisation. Instagram fetches media through signed, expiring `/public/media/<org>/<id>` links. Instagram webhooks arrive at `/webhooks/instagram/<org>` (verify token derived per org; POST bodies must match `X-Hub-Signature-256` with that org's app secret).
- Bind loopback by default. Do not print secrets or dump `process.env`.
- YouTube, LinkedIn, Instagram, X, Hashnode, Slack, and Reddit are the networks. Reddit uses OAuth (web app, `duration=permanent`, 1-hour access tokens refreshed in `src/reddit.js`); since November 2025 new Reddit API apps need approval, so without keys Reddit runs in manual mode: `post_reddit` returns a pre-filled `submitUrl` (Reddit's own submit page) and nothing is posted until the user clicks Post; `POST /api/reddit/track` saves the resulting link. Reddit posts are text or link only, and the agent must post only to a subreddit the user named, check its rules first, and never cross-post. Slack uses a pasted bot token (Slack OAuth needs an https redirect), with a manifest served from `/api/connectors` for setup. Hashnode uses a personal access token (no OAuth) and its GraphQL API only works for blogs on Hashnode Pro. Brew runs on the organisation's `AGENT_PROVIDER` (Grok via `src/grok.js`, or Claude via `src/claude.js`, raw HTTP to keep zero dependencies); clips are always Grok Imagine. Video reviews can use Grok, Claude, or OpenAI. Brew's history is OpenAI-shaped; Claude replies keep their raw blocks in `_claude`, and thinking is replayed only within the current request (Brew trims old turns, which would invalidate older thinking blocks).
- Keep the app runnable with zero npm dependencies. Wrangler is a devDependency for the Cloudflare deploy only (`wrangler.jsonc`, `worker/`); `src/` must never import `cloudflare:*` modules. All persistence goes through `src/storage.js` (files on Node; on Workers, `worker/storage.js` keeps JSON in D1 and videos in R2 when bound, else in D1 pieces with oldest-first cleanup), so never touch `fs` for app data directly, and never do I/O, timers, or random values at module load (Workers forbid it). The dashboard source is `web/` (Vite, React, shadcn/ui, Tailwind). It builds into `public/`, and that output is committed. After changing `web/`, run `npm run web:build`.
- Dashboard colors come from `PALETTE` in `web/src/theme.ts`. Derive new colors from `--p1`..`--p4` in `web/src/index.css`, not from hard-coded values.
- The server serves files from `public/` and falls back to `index.html` for client routes. Keep `/api/*`, `/public/*`, `/webhooks/*`, and `/mcp` out of that fallback.
- Tests: `npm test`.
- The Chrome extension is `extension/` (MV3 side panel, Vite + React, its own `package.json`; build with `npm run ext:build`, output `extension/dist`, not committed). It works in the user's own tabs with their own Anthropic/xAI keys and no network connections; signing in (the dashboard's Clerk session via `syncHost`) only syncs runs through `GET/PUT /api/extension/runs` (`src/extension.js`), and posts it records go into the organisation's Posts list. Every publish click, Enter in a composer, or Mod+Enter must pass the approval gate in `extension/src/agent/tools.ts`; never add a way around it. Page scripts are injected functions (`extension/src/agent/page.ts`) and must stay self-contained. The extension id is pinned by `key` in `extension/public/manifest.json` and must be listed in `CLERK_AUTHORIZED_PARTIES`.
